# 가격 규칙

예약 금액은 **화면이 아니라 DB 트리거**(`apply_reservation_pass_pricing`, 최신 정의는
`supabase/migrations/0057_stackable_coupon.sql`)가 정합니다. 화면이 보낸 금액은 무시하고
다시 계산하므로, 개발자 도구로 금액을 바꿔 결제할 수 없습니다.

이 규칙을 바꾸면 아래 세 곳을 같이 바꾸고 `npm test`로 확인합니다.

| 위치 | 역할 |
| --- | --- |
| `apply_reservation_pass_pricing()` (새 마이그레이션) | 실제 저장 금액 |
| `src/lib/discount.ts`, `src/lib/coupon.ts`, `src/lib/reservationPrice.ts` | 화면 표시·결제 직전 대조 |
| `supabase/functions/_shared/pricing.ts` | 정기결제 청구 금액 |
| `supabase/tests/pricing.test.ts` | 위 규칙을 실제 Postgres에서 고정하는 테스트 |

## 1. 기본

- **1인 금액 × 인원.** 할인은 1인 금액에 먼저 적용하고 인원을 곱합니다.
- 금액은 **10원 단위 내림** (`discounted_price`). 예: 9,990원 15% → 8,490원.
- 판매 중(`is_active`)이 아닌 이용권 이름으로는 회원이 예약할 수 없습니다. 관리자·서버는 예외(수기 예약).
- `min_people`보다 적으면 거절합니다.
- 이름에 "문의"가 들어간 예약은 금액을 비웁니다(상담용).

## 2. 이용권 할인 (설정 > 할인 탭)

- 할인율과 **마감일**이 둘 다 있어야 적용됩니다. 마감일 없는 할인은 저장되지 않습니다.
- 기준은 **예약한 날**(한국 시간)입니다. 이용일이 아닙니다.
- 한 번 정해진 할인율(`discount_percent_at_booking`)은 예약을 고쳐도 유지됩니다. 할인이 끝난
  뒤 인원을 늘려도 예약 당시 할인율로 다시 계산합니다.

## 3. 쿠폰

- 본인 쿠폰, 미사용(`issued`) 상태, 할인율 > 0, 범위(시간권·종일권·주간권·월권·전체)가 맞아야 합니다.
  범위는 이용권 이름에 "시간/종일/주간/월권"이 들어가는지로 판단합니다(`pass_matches_coupon_scope`).
- **중복 불가(기본):** 이용권 할인과 쿠폰 중 **큰 쪽 하나만** 정가에 적용합니다.
  - 정가 200,000 / 이용권 20% / 쿠폰 10% → 160,000
- **중복 가능(발급 시 선택):** 이용권 할인 뒤에 쿠폰을 **순차로** 깎습니다. 더하지 않습니다(합이 100%를 넘지 않게).
  - 14,000 → 20% → 11,200 → 10% → 10,080
- 쿠폰은 결제가 확정될 때 사용 처리되고, 전액 환불되면 되돌려집니다. 결제가 끝난 예약의 쿠폰은 바꿀 수 없습니다.

## 4. 정기결제 (월권 자동결제)

- 첫 결제: 위 규칙 그대로.
- 다음 회차부터: **청구하는 날** 그 이용권에 할인이 걸려 있으면 할인가, 없으면 정가.
  다만 처음 가입한 금액(`subscriptions.amount`)보다 비싸게 청구하지 않습니다(정가 인상 시 보호).
- 기간은 영업일 24일(4주, 휴무 제외)이며, 휴무일을 추가하면 이미 산 이용권 종료일을 늘립니다.
